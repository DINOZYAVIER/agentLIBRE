# Functions

An agentFUNCTION is the only product-level entry point for model-backed work.
`agl run`, bare `agl`, and `agl serve` resolve either `--function` or the
workspace default from `.agl/workspace.toml`. There is no raw inference command
or local inference config override.

## Package authority

A Function is resolved from the package graph. Its payload owns:

- the system prompt and Tool policy;
- selected Skills and delegation declarations;
- one package-bound Model reference and exact profile id;
- per-attempt generation policy, including the output limit and Tool mode.

The referenced Model package owns the load shape: ordered digest-bound artifact
files, context and batch sizes, cache types, device predicate, projector, and
optional draft/MTP declaration. A Function cannot inject model paths, native
arguments, or backend JSON.

The runtime composes the resolved Function and Model payloads into typed inputs.
`agl-model::resolve_execution_plan` checks the Model v3 schema and static host
capabilities and returns an opaque `ModelExecutionPlan`. Live RAM/VRAM admission,
queueing, process supervision, and generation belong to
`agl-inference::InferenceHost`.

## Workspace selection

An initialized workspace declares one default Function:

```toml
[functions]
default = "gemma4-12b"
```

An existing workspace with a missing or invalid default fails with a repair
error. It never falls back to an unbound model. Outside a workspace, the runtime
may select the built-in default recorded by the current package composition.

Examples:

```bash
agl run --prompt "Summarize this workspace"
agl run --function gemma4-12b --prompt "Reply once."
agl serve --function gemma4-12b
agl function list
agl function show gemma4-12b
```

`--max-output-tokens`, `--tool-mode`, and `--skill` affect the Function turn
through typed product inputs. They do not expose native inference configuration.
Changing the Function or its package graph requires a new admitted runtime
composition.

## Runtime context

The chat runtime combines the Function prompt with admitted Skill context,
visible Tool schemas, memory context, and runtime identity. Tool visibility is
computed by kernel policy before inference. llama.cpp renders the selected model
template and lazily applies Tool grammar; AGL parses and validates the raw output
before executing any Tool.

Subagents receive a separately resolved Function/Model composition bounded by
the parent's delegation authority. They cannot inherit an arbitrary native
session or widen the parent's Tool set.

## Evidence

Every admitted attempt is correlated by `RunId`, `TurnId`, and `AttemptId`.
The durable inference journal is authoritative for attempt transitions. Derived
run evidence binds:

- the exact Function/Model package graph and payload digests;
- profile and opaque plan digest;
- ordered artifact files and descriptor identity;
- selected engine executable, llama.cpp commit, and device receipt;
- visible Tool/schema and prompt-template identity;
- admission resources, raw generated bytes, parsed output, and terminal result.

`runtime-resolution.json` and event streams are projections of admitted product
and inference state; they are not alternate configuration inputs.

## Model installation

`agl init`, `agl model pull`, and `agl model import` acquire files declared by
the Model package. Publication uses the model install transaction and records the
exact digest-bound files. A run resolves only those installed records; cache
search and filename discovery cannot add runtime artifacts.

The removed surfaces have no compatibility path:

- `agl inference run` and `agl inference serve`;
- `--config` on `run` or `serve`;
- `$AGL_HOME/config/inference/local.toml` and named inference profiles;
- Function-owned inference TOML files, raw model paths, and backend overrides.
